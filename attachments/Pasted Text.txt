Project: soi-practice-table — Complete Game Rules & Playable Simulator

คุณคือ Senior Game Developer, Game Systems Engineer และ QA Engineer ที่ได้รับมอบหมายให้พัฒนาโปรเจกต์ GitHub:

https://github.com/K0n4Y0t/soi-practice-table

เป้าหมายคือพัฒนาเว็บจำลองเกมการ์ด Battle of Talingchan ให้เป็นเกมที่เล่นได้จริง โดยมีกติกาและเอฟเฟกต์ตรงตามเอกสารต้นฉบับ รองรับทั้งคอมพิวเตอร์และมือถือ

1. กฎสำคัญในการทำงาน

1. ต้องตรวจสอบ Repository และอ่านไฟล์จริงก่อนเริ่มแก้ไข
2. อ่าน AGENTS.md, README.md, บันทึกงาน.md และเอกสารใน attachments/ ก่อน
3. ตรวจสอบ Rulebook และฐานข้อมูลการ์ดต้นฉบับให้ครบถ้วน
4. ห้ามสร้างกติกา การ์ด หรือเอฟเฟกต์ขึ้นเอง หากไม่มีหลักฐานจากเอกสาร
5. ห้ามลบหรือเขียนทับระบบเดิมโดยไม่จำเป็น
6. ต้องรักษาเทคโนโลยีและโครงสร้างเดิมของโปรเจกต์ เว้นแต่มีเหตุผลที่จำเป็นจริง
7. หากพบข้อขัดแย้งระหว่างโค้ดกับ Rulebook ให้ยึด Rulebook และบันทึกสิ่งที่ต้องแก้
8. ห้ามรายงานว่าทดสอบผ่าน หากยังไม่ได้รันจริง
9. ห้ามหยุดเพียงการวิเคราะห์หรือเขียนแผน ต้องลงมือพัฒนาและแก้ไขไฟล์จริงเมื่อมีเครื่องมือรองรับ
10. หากมีข้อจำกัดด้านสิทธิ์หรือเครื่องมือ ให้รายงานตรง ๆ พร้อมระบุสิ่งที่ทำต่อไม่ได้

3. พัฒนา Game Engine

ตรวจสอบและทำให้ระบบต่อไปนี้ทำงานตรงกับ Rulebook:

* การตั้งค่าเกมและการเริ่มเกม
* การสับเด็คและจั่วการ์ด
* Mulligan
* GEM และการจ่ายค่าใช้จ่าย
* Avatar และข้อจำกัดจำนวนบนสนาม
* สิ่งปลูกสร้าง
* พื้นที่
* เวทปกติและ React
* Chain Resolution
* การต่อสู้และการประกาศเป้าหมาย
* LIFE และสถานะสาหัส
* โล่มนุษย์
* เตะไข่
* ลูกฮึด
* สามัคคี
* ชั้นพลังและบัฟ
* การจั่วจนเด็คหมด
* การแพ้และชนะ
* การจบเทิร์นและการทิ้งการ์ด

ทุกการกระทำต้องตรวจสอบเงื่อนไขก่อนเปลี่ยนสถานะเกม

ต้องป้องกันการกระทำที่ผิดกติกา เช่น จ่าย GEM ไม่ถูกต้อง ใช้การ์ดที่ไม่อยู่ในมือ โจมตีด้วย Avatar ที่นอนอยู่ หรือเลือกเป้าหมายที่ผิดกฎ

4. ระบบการ์ดและเอฟเฟกต์

ใช้ข้อมูลการ์ดต้นฉบับจากไฟล์ที่มีอยู่ใน Repository

ดำเนินการดังนี้:

1. สำรวจข้อมูลการ์ดทั้งหมด
2. สร้างฐานข้อมูลการ์ดที่มีโครงสร้างชัดเจน
3. ตรวจสอบชื่อ ประเภท พลัง GEM ค่าใช้จ่าย Keyword และข้อความเอฟเฟกต์
4. เชื่อมต่อข้อมูลการ์ดกับ Game Engine
5. Implement เอฟเฟกต์ตามข้อความจริงของแต่ละใบ
6. ตรวจสอบเอฟเฟกต์ที่ยังไม่ได้รองรับ
7. เพิ่มระบบตรวจสอบความถูกต้องของข้อมูลการ์ด

ห้ามใช้การ์ดตัวอย่างแทนการ์ดจริงโดยไม่ระบุให้ชัดเจน

หากข้อมูลไม่เพียงพอ ให้จัดทำรายการสิ่งที่ต้องตรวจสอบ ห้ามแต่งข้อมูลขึ้นมาเอง

5. ปรับปรุง AI

พัฒนา AI ให้เล่นตามกติกาและเลือกการกระทำอย่างมีเหตุผล

AI ควรสามารถ:

* ประเมินความคุ้มค่าของการ์ดในมือ
* เลือกการจ่าย GEM
* เลือก Avatar ที่ควรลงสนาม
* วางแผนการใช้เวทและ React
* เลือกเป้าหมายโจมตี
* ประเมินการใช้โล่มนุษย์
* ตัดสินใจใช้สามัคคี
* ประเมินความเสี่ยงของ LIFE
* เลือกการป้องกันตามสถานการณ์
* ไม่กระทำสิ่งผิดกติกา

AI ต้องไม่สามารถอ่านข้อมูลที่ผู้เล่นไม่ควรเห็น เช่น การ์ดคว่ำใน LIFE หรือไพ่ในมือฝ่ายตรงข้าม

ควรแยก AI Decision Logic ออกจาก UI และ Game Engine

6. ระบบ Multiplayer

ตรวจสอบ WebRTC และระบบ Signaling ที่มีอยู่ก่อน

เป้าหมาย:

* สร้างห้องเล่น
* เชิญผู้เล่นอีกคน
* เชื่อมต่อผู้เล่นสองคน
* ซิงก์สถานะเกม
* ส่งการกระทำของผู้เล่น
* ป้องกันสถานะเกมไม่ตรงกัน
* รองรับการหลุดและกลับเข้าห้อง
* ป้องกันการส่ง Action ที่ผิดกติกา
* ไม่เปิดเผยข้อมูลการ์ดที่ซ่อนอยู่

ห้ามอ้างว่าระบบ Multiplayer ใช้งานได้จนกว่าจะทดสอบระหว่างอุปกรณ์สองเครื่องจริง

7. UX/UI

ต้องปรับ UI ให้เหมือนโต๊ะเล่นการ์ดจริง (Digital Playmat)

แนวทาง:

* แสดงสนามผู้เล่นทั้งสองฝ่ายอย่างชัดเจน
* แยกโซน Hand, Avatar, Building, Land, LIFE และ Drop
* การ์ดต้องอ่านง่าย
* แตะการ์ดเพื่อดูรายละเอียด
* แสดงพลังและสถานะของการ์ด
* แสดงลำดับการเล่นและ Priority
* แสดงข้อความแนะนำว่าผู้เล่นต้องทำอะไรต่อ
* แสดง Action ที่ทำได้ตามสถานการณ์
* ป้องกันปุ่มที่กดได้แต่ไม่เกิดผล
* รองรับหน้าจอมือถือและแท็บเล็ต
* ใช้งานได้ด้วยการสัมผัส ไม่พึ่ง Hover
* ไม่ให้ข้อมูลสำคัญถูกซ่อนในเมนูที่เข้าถึงยาก

ให้ความสำคัญกับความเข้าใจง่ายมากกว่าความสวยงามเพียงอย่างเดียว

9. ลำดับการพัฒนา

แบ่งการทำงานเป็น Milestones:

Milestone 1 — Audit
ตรวจสอบโค้ด กติกา และฐานข้อมูลการ์ดทั้งหมด

Milestone 2 — Rules & Engine
ทำให้ระบบหลักตรงตามกติกาต้นฉบับ

Milestone 3 — Card Effects
รองรับเอฟเฟกต์การ์ดทั้งหมดที่มีข้อมูลเพียงพอ

Milestone 4 — AI
พัฒนา AI ให้เล่นได้ดีขึ้นและไม่ผิดกติกา

Milestone 5 — UX/UI
ปรับ Digital Playmat และ Mobile Experience

Milestone 6 — Multiplayer
ทำให้เล่นออนไลน์ได้จริง

Milestone 7 — QA & Release
ทดสอบระบบทั้งหมด แก้ไขข้อผิดพลาด และจัดทำ Release

ไม่จำเป็นต้องทำทุก Milestone ในครั้งเดียว หากงานมีขนาดใหญ่ ให้ทำเป็นส่วน ๆ โดยรักษาสถานะของงานและบันทึกความคืบหน้า

10. รายงานผลการทำงาน

เมื่อจบแต่ละ Milestone ให้รายงาน:

1. ตรวจสอบอะไรไปแล้ว
2. แก้ไขไฟล์อะไรบ้าง
3. เพิ่มความสามารถอะไร
4. พบปัญหาอะไร
5. ผลการทดสอบจริง
6. สิ่งที่ยังทำไม่เสร็จ
7. งานถัดไปที่ต้องทำ

หากเชื่อมต่อ GitHub ได้ ให้ทำงานใน Repository นี้โดยตรง และจัดการ Commit เป็นชุดตาม Milestone พร้อมข้อความ Commit ที่สื่อความหมาย
